## 一、系统终态规格

**一句话**：Mac Pro 本地运行的 2830 万篇生物医学文献语义检索系统——中文自然语言提问，亚秒级返回真实 PMID（零幻觉构造），带完整审计链与自动运维。

| 组件 | 规格 |
|---|---|
| 语料 | PubMed 2026 baseline，**28,337,072 篇**（=全部带摘要记录；已排除 1,166 万条 title-only，快照 2026-01） |
| 编码模型 | Qwen3-Embedding-8B（bf16，Apache-2.0，开原验证顶点） |
| 向量 | 4096 维 fp32 原件 432GiB（npy 底片）+ Qdrant pq4 量化索引（磁盘量化码算术 58GB；进程实测 RSS 45.2 GiB，mmap 惰性加载） |
| 检索 | Qdrant 1.19.1，HNSW(m=16, ef_construct=128)，双 collection（52.9 万子集库 pubmed_v2 含 BM25 混合腿 / 28.3M 全量库 pubmed_full） |
| 查询链 | agent 层（中文→英文改写）→ 查询编码（8B，迷你窗/CPU）→ Qdrant 检索 → PMID 偏移索引取摘要（<1ms，0.5GB SQLite）→ 带引文综合 |

| 运维 | 窗口编排（五步断言+溯源+owner 登记）· vLLM 守卫 v4（时间戳窗口识别）· 值守日志 · 检查点续跑 |
| 合规 | license 全清（PubMed 署名/私用、模型 Apache/MIT/public domain）；PRISMA 边界声明（不替代多库检索义务） |

## 二、四层终表 v3（全部实测，n 与口径注明）

### 层 1 · 模型与基建选型（P0，WB 已终验）
- 吞吐锚点：TP2 20.76 / 单卡 37.42 / DP2 41.5+41.7 docs/s；FP8 无实质加速（±10%）→ Macx 裁定 bf16 一路到底
- 量化矩阵（1 万条）：**pq4 召回 100%/p50 16.6ms 胜出**；int8/pq8 次之；pq16/pq32 出局
- MedCPT 对照（C-1 闸门）：**8B 显著优于领域专训**（@1 p=0.039、@100 p=0.031，单变量+预算稳健）——项目最硬结论

### 层 2 · 子集库（P1，52.9 万篇，n=21 已知项）
- 生产链 hybrid RRF→bge：@5=85.7%、@10=95.2%、@100=100%（"不劣"定型口径）
- 稀疏腿/翻译/精排增益：n=21 不可区分（正确配对 p=1.000/0.250/1.000）→ 待扩样议题

### 层 3 · 全量库（P2，28.3M，v93=93 查询=31 目标×3 形态）

**可比性前提（B2 披露）**：两库筛选规则不同——子集库=MeSH 命中（529,091，含 title-only 记录），全量库=有摘要（28,337,072，不含 title-only）。**"全量⊇子集"不成立**：3 篇子集内目标（16291908/36076727/36300975）为 title-only，不在全量库（pmid_offset.db 已核缺席）。

- 总体（分母 93）：@1=40.9%、@5=65.6%、@10=77.4%、@100=89.2%（83/93，miss=1）
- 目标在库内（分母 84=93−9；9 = 3 篇 title-only 目标 × 3 形态）：@100=**98.8%**（83/84）
- **同一批 21 个目标在 v93 中的 3 形态（63 条查询）、且目标在两库均在库**（分母 54=18 目标×3 形态）：@100=**98.1%**（53/54）——与子集库同口径对照（子集侧剔除同 3 篇后 18/18=100%）：**两库检索质量同档（98-100%），规模零衰减**。注意与 v63（21 原版+42 变体，子集库 @100=93.7%）是不同查询集，不可直接比大小
- 分层：英文技术查询最强（@10=90.3%）、口语化中文最难（@1=29.0%）→ agent 层查询规范化改写为免费提升路径
